# AI Image Restoration ｜ AI 图片智能修复

**Windows 本地离线运行的图片文字 / 水印去除与图像修复工具**

`Detection → Mask → AI Inpainting → Post-Processing → Auto Quality Check`

![app icon](assets/app_icon_preview.png)

上传图片 → 在要去掉的文字 / 水印上涂一下 → 点「✨ AI 去除」→ 下载结果。
全程本地运行，**图片不上传云端**，模型可离线使用。

> ⚠️ 请只处理你本人拍摄、创作，或已获得权利人授权编辑的图片。
>
> ⚠️ 马赛克等**已经彻底破坏像素**的区域，AI 只能根据周围画面「推测式重建」，
> **无法还原真实原始内容**。本项目不做任何 “100% 恢复” 的承诺。

## 1. 项目简介

| 项目 | 说明 |
| --- | --- |
| 定位 | 面向个人用户的**本地离线**图片文字 / 水印去除工具 |
| 解决的问题 | 照片上的网址、日期戳、账号 ID、半透明水印、平铺水印等叠加内容，想要一张干净图 |
| 技术路线 | 不做模糊、不做裁剪、不用纯色覆盖；用 OCR 定位文字，用图像修复模型按周围纹理**重建**被遮挡区域 |
| 核心流程 | 检测 → Mask → AI 修复 → 后处理 → 自动质量验证 |
| 运行方式 | Windows 桌面本地运行，Web UI（Gradio），默认 `127.0.0.1:7860`，端口被占用时自动向后寻找 |
| 加速 | 自动检测 CUDA；无 NVIDIA 显卡时自动切 CPU，功能一致（速度较慢） |

项目的工程重点**不在训练模型**，而在于：如何得到一张正确的掩膜、如何控制修改范围不越界、
如何让修复区域与周围在光照和纹理上自然衔接，以及如何用可量化的指标验证这些结论。

## 2. 核心功能

三种处理模式在代码上是**相互隔离的独立模块**（`core/modes/`），共用同一套底层修复引擎
（`core/pipeline.py`），但检测逻辑互不共享。修改任一模式的参数，不会影响另外两个模式
——这一点由自动化测试实测验证（见第 8 节）。

### 2.1 模式 A：智能自动识别 ｜ 🧪 实验性 / 待完善

上传图片后由程序自行判断“哪里像水印”，用户确认后再修复。

- 依据 **类型 + 位置 + 尺寸 + 重复性 + 半透明响应 + 人脸冲突** 做启发式打分，输出分层的候选区域；
- 支持文字、网址 URL、日期、时间戳、账号 ID、半透明水印、重复 / 平铺水印、Logo 候选、马赛克区域等候选类型。

**请勿将它理解为成熟功能。** 本模式由人工设计的启发式规则驱动，
**没有标注数据集，因此不提供“准确率 / 召回率”这类指标**。
纯图形 Logo、非文字的复杂水印只能靠位置与重复性推测；实测也曾把格纹布料误判为水印
（现已加入“半透明响应覆盖率过高即判不可信”的守卫，并把视觉类候选默认设为**不勾选**）。
它的定位是**给用户一个建议起点**，最终仍需人工确认。

### 2.2 模式 B：自动文字水印去除 ｜ ✅ 主要功能

适用于图上文字较多、希望批量清理的场景。**OCR 能识别出来的文字默认全部划入待去除区域**
（不做“是不是水印”的二次筛选），因此“优先不漏”，页面上可在候选表格里取消不需要的行。

| 能力 | 实现要点 |
| --- | --- |
| OCR | PP-OCRv4（RapidOCR + ONNXRuntime），中文 / 英文 / 数字 |
| 多尺度检测 | 五路 OCR 证据：① 全图正读 ② 整图旋转 ±25°/±45° ③ 笔画聚类逐块去倾斜放大 ④ 原分辨率高清分块兜底 ⑤ 局部高分辨率识别 |
| 局部检测 / LOHR | 仅在人脸框、笔画聚类得到的**小 ROI** 上放大 2x 与 3x 各读一次，**只保留两次都读到的结果**；全局置信度阈值保持不变 |
| Mask 优化 | 先按笔画贴合生成掩膜（彩色感知对比 + 填补字身空洞），再按图像内容**收紧**；水印核心面积超过画面 25% 时自动内缩并提示 |
| 实例保护 | 模板匹配 / 点阵展开补出的重复水印实例没有 OCR 框，收紧时会被误删；对“被保留不足 75%”的实例按检测形状整块保留 |
| 人脸保护 | YuNet 检测人脸 + 5 关键点，生成面部与五官硬保护掩膜；五官被遮挡过密时**丢弃过大的遮挡块**，只修细小碎片 |
| AI 修复 | LaMa（big-lama, TorchScript），ROI 优先在原始分辨率上局部重建；显存不足时自动分块，再退回 OpenCV Telea |
| 批量处理 | 选择文件夹 → 逐张**独立**检测与修复（绝不复制上一张的掩膜），单张失败不中断；同名自动编号，绝不覆盖原图 |
| 检测缓存 | 以**图片内容指纹 + 参数指纹**为键的 LRU 缓存，同一张图重复检测直接命中 |

### 2.3 模式 C：手动区域修复 ｜ ✅ 稳定的局部修复模式

用户用画笔涂出要去掉的位置，程序只修涂抹范围，**完全不引用任何自动检测结果**。
因为“要修哪里”由人给出，语义正确，所以它是本项目**质量最稳定的基线模式**。

| 能力 | 实现要点 |
| --- | --- |
| 手动选择 | 画笔 / 橡皮擦 / 撤销 / 重做 / 清除；Mask 不额外扩张，交由修复引擎按内容收紧 |
| ROI-first | 掩膜包围盒加边距后占比 ≤90% 时，只用**一个 ROI** 做一次推理、一次融合，避免整图缩放丢细节 |
| LaMa 局部修复 | 在 ROI 内按**原始分辨率**推理，再按记录的偏移量贴回原图 |
| 局部色调匹配 | 只用**掩膜外**像素估计“期望光照场”并向内插值，只施加低频偏移，且校正强度从边界向内部衰减到 0 |
| 高频纹理匹配 | 把周围真实高频用 `cv2.inpaint` 延续进掩膜并按能量比匹配；修复区偏锐时反向衰减 |
| 人脸保护 | 同 B 模式：YuNet + 五官硬保护；面部模式下自动降低扩张、羽化与色调校正强度 |
| 质量检查 | 输出掩膜外改动比例、亮度 / 色差、高频比、清晰度比、残留消除量、五官区最大改动，并写入 JSON 报告 |

## 4. 系统架构

```
                    输入图片
                       │
        ┌──────────────┴───────────────┐
        │                              │
   A/B：文字检测                  C：用户手动涂抹
   （五路 OCR 证据链）              （画笔 / 橡皮擦）
        │                              │
        └──────────────┬───────────────┘
                       ▼
                  Mask 优化
       （贴合笔画 → 按内容收紧 → 实例保护）
                       │
                       ▼
                  人脸保护
       （YuNet + 五官硬保护掩膜 + 修复计划）
                       │
                       ▼
              双掩膜 + ROI 构建
     （repair_mask 100% 替换 / blend_mask 过渡带）
                       │
                       ▼
                  LaMa 修复
       （ROI 原生分辨率 → 分块 → 整图，逐级降级）
                       │
                       ▼
            颜色 / 纹理处理与融合
     （局部光照场校正 → 高频纹理匹配 → 平滑羽化融合）
                       │
                       ▼
                  质量检查
     （掩膜外改动 / 亮度色差 / 高频比 / 残留量）
                       │
                       ▼
                  输出图片
```

主要模块职责：

| 模块 | 职责 |
| --- | --- |
| `app.py` | 入口：端口自动选择、设备检测、启动 Web UI |
| `config.py` | 目录、默认参数、CUDA / CPU 设备探测、日志初始化 |
| `core/modes/` | A / B / C 三个独立模式（懒加载，互不 import） |
| `core/auto_detect.py` | 多路 OCR 证据收集、候选合并、模板聚类与点阵展开、检测缓存 |
| `core/pipeline.py` | 修复编排：Mask 收紧 → 人脸保护 → 双掩膜 → ROI → LaMa → 后处理 → 质检 |
| `core/inpainting.py` | LaMa 后端、ROI / 分块 / 整图三种推理路径、OpenCV 兜底 |
| `core/mask_refiner.py` | 按 OCR 框 / 半透明证据 / 对比度残差收紧掩膜、边界裁剪与越界度量 |
| `core/face_protector.py` | 人脸检测、五官掩膜、修复计划（局部优先、面部收紧） |
| `core/image_processor.py` | 图片归一化、局部光照 / 纹理匹配、融合、质检、落盘 |
| `core/batch_processor.py` | 批量扫描、逐张处理、输出目录与文件命名 |
| `ui/interface.py` | Gradio 界面与全部回调 |

## 5. 核心技术难点与解决方案

以下 5 个问题都是开发过程中**真实出现并被定位、修复**的，括号内为实测数据。

### 5.1 小尺寸文字水印漏检

**现象**：512×1080 人像上、眼睛附近 24px 高的水印文字，整图 1x / 1.5x / 2x OCR 读数全为 0。

**难点**：这不是“调阈值”能解决的问题——直接降低全局置信度阈值会让草地、布纹、头发产生大量假阳性，
与小字召回率直接冲突。

**方案**：只在人脸框与笔画聚类得到的**小 ROI** 上放大 2x / 3x 各读一次，
**只保留两个倍率都读到的结果**（多尺度一致性），全局阈值保持不变。
真实文字在多个倍率下都应被读到，而噪声往往只在某个偶然倍率触发。

**效果**：24px / 20px / 16px 小字可稳定检出；对**没有水印**的同一人脸区域做同样放大，读数为 0 条。

### 5.2 LaMa 在“零余量孔洞”下把文字抄回来

**现象**：水印去掉后仍能看到轮廓，红色文字位置出现金黄色块，残留比例 21.4%。

**难点**：B 模式的掩膜是紧贴笔画的自动掩膜，`clip_to_user(allow_px=0)` 会把计划中的扩张整段裁掉，
送进模型的是**零余量孔洞**，LaMa 顺着孔洞两侧像素复现了原文字；
但直接扩大最终掩膜又会重新引入“涂抹感”。

**方案**：新增 `hole_grow`——**只把送进模型的孔洞扩开 6px，写回范围完全不变**。

**效果**：残留 **21.4% → 0.2%**，而 Mask 面积 **4.76% → 4.76%**，即真正被修改的范围没有变大。

### 5.3 掩膜收紧把已检测到的重复水印实例误删

**现象**：检测阶段找到了全部重复水印，修复后却有一批完全没被处理，单个实例的掩膜覆盖率 100% → 0%。

**难点**：删除发生在“检测之后、修复之前”的中间层，检测召回率看起来正常，问题被掩盖。

**方案**：做**实例级三段统计**（检测命中 / 掩膜覆盖 / 修复后残留）定位到收紧阶段，
并加入 `keep_user_instances`：某实例被收紧掉超过 25% 即按检测到的形状整块保留
（面积不超过检测结果，因此不是扩大掩膜）。

**效果**：真实案例 6 张图 / 54 个实例，成功数 **26 → 47**，掩膜对文字像素覆盖率 **79% → 94%**。

### 5.4 修复区与周围的光照 / 纹理不一致（阴影、色块、塑料感）

**现象**：修复区比周围偏亮 / 偏暗 / 偏灰，或在人脸皮肤上显得过于光滑。

**难点**：早期用**整图均值**做颜色校正，但照片存在光照渐变，整图均值不代表局部
（实测修复区与周围亮度差达 −21 灰阶）。

**方案**：三层处理——
① 局部光照匹配：只用掩膜外像素做归一化卷积 `blur(x·w)/blur(w)`，向掩膜内插值出“期望光照场”，
只施加低频偏移以保留模型生成的纹理，并让校正强度从边界向中心衰减到 0；
② 高频纹理匹配：把周围真实高频延续进掩膜并按能量比匹配，偏锐时反向衰减；
③ 平滑羽化融合：alpha 在 `repair_mask` 内恒为 1，仅在过渡带做 smoothstep。

**效果**：已保存的 36 份修复报告中，水印局部亮度偏移消除量中位数 81%（最高 97%）。

### 5.5 模式耦合风险：改 A / B 会不会悄悄改坏 C

**难点**：C 是已验证的质量基线，这类耦合不会报错，只表现为“结果变了”，很难靠人眼发现。

**方案**：三层保障——
① 代码层：三个模式是独立模块，C 不引用任何检测相关代码；
② 加载层：`importlib` 懒加载，跑 C 时 OCR / 自动检测模块**根本不进入 `sys.modules`**；
③ 验证层：`tests/test_mode_isolation.py` 用**子进程实测模块清单**，
并比较“修改 A/B 参数后 C 输出”的每个像素。

**效果**：6 项隔离测试全部通过；C 的修复结果与手动基线路径逐像素一致（容差 ≤3 灰阶），掩膜外 0 改动。

## 6. 性能

**当前测试样例结果（本机 RTX 4060 Laptop / CUDA，1280×800）**：

| 阶段 | 耗时 |
| --- | --- |
| 自动检测（A/B） | 1.8 ~ 10.8 s（其中 OCR 0.25~5.9s、旋转扫描 1.7~5.3s、局部放大 OCR 0.05~2.9s） |
| LaMa 修复 | 0.25 ~ 5.3 s |
| 后处理 | 0.03 ~ 0.09 s |
| Mask 收紧 | 0.45 ~ 0.9 s |
| 单张总计 | 约 6 ~ 13 s |

**结论：瓶颈在检测阶段，而不是模型推理。** 因此优化方向是检测缓存与时间预算，
而不是更换模型：

- **检测缓存**：同一张图（内容未变）第二次检测直接命中缓存，耗时从秒级降到毫秒级；
- **时间预算**：每一路检测都有毫秒级预算，超预算即停止，避免在文字密集图上无限扫描；
- **降采样扫描**：旋转扫描在缩小后的图上进行；
- **按需加载**：手动模式启动路径不加载任何 OCR / 自动检测模块。

> 说明：以上均为**当前测试样例**的实测结果。实际耗时受图片尺寸、检测路径与硬件影响，
> 不代表系统的平均性能；CPU 模式下处理高分辨率图片明显更慢。

## 7. 质量验证

项目不只验证“程序有没有报错”，还验证“修复得对不对、有没有改坏别的地方”。

### 7.1 自动质检指标

每次修复都会生成一份质检结果（同时写入 JSON 报告），包含：

| 指标 | 含义 | 期望 |
| --- | --- | --- |
| `outside_change_ratio` | 掩膜**之外**被改动的像素比例 | 应为 0 |
| `edge_luma_delta` | 修复区与外围邻域的亮度差（并与原图该处的差做对比） | 不应比原图更差 |
| `edge_chroma_delta` | 修复区与外围的色差 Δa / Δb | 越小越好 |
| `hf_ratio` | 修复区与外围的高频能量比 | 接近 1（过小=涂抹感，过大=颗粒感） |
| `sharp_ratio` | 修复区与外围的清晰度比 | 接近 1 |
| `residue_cut` | 水印局部亮度偏移的消除比例 | 越大越好 |
| `face_outside_change` | 五官核心区（掩膜之外）的最大改动 | 应为 0 |

### 7.2 已验证结果

| 验证项 | 结果 | 出处 |
| --- | --- | --- |
| **范围外改动（range-outside modification）** | **0.000%** | 已保存的 36 份真实修复报告，`outside_change_ratio` 全部为 0 |
| **笔刷泄漏（brush leakage）** | **0.00%** | `tests/quality_round4.py`，11 个场景（含真值评分） |
| **五官区最大变化（facial feature max area change）** | **0.0** | `quality_round4` 人脸场景 + 修复报告中的 `face_outside_change` |
| 范围外改动（第四轮 11 场景） | 0.00% ~ 0.05% | `quality_round4` |
| 水印残留 | 21.4% → 0.2% | 孔洞扩张前后对比 |
| 修改范围 | Mask 面积 4.76% → 4.76% | 同上，证明未扩大 |
| 重复水印实例成功率 | 26/54 → 47/54 | 真实案例（6 张图） |
| 大图坐标映射偏差 | 3840×2160 上为 **1 px（0.03%）** | 真实浏览器 + 自动化测试 |

> 注：`五官区最大变化 = 0.0` 表示**未被水印覆盖的五官像素与原图保持一致**；
> `笔刷泄漏 0.00%` 表示最终改动**完全落在**收紧后的掩膜内，不会暴露笔刷形状。
> 对于被不透明遮挡的区域，原始像素已经丢失，AI 只能推测重建，误差必然偏高——
> 这是方法的固有边界，本项目不做“100% 无误”的表述。

| 模型 | 用途 | 文件 | 大小 | 是否必需 |

### LaMa 权重获取方式

放置位置：`models/big-lama.pt`

方式 A：直接下载（真实可用的官方 release 地址，详见 [`models/README.md`](models/README.md)）

```bat
curl -L -o models\big-lama.pt https://github.com/enesmsahin/simple-lama-inpainting/releases/download/v0.1.0/big-lama.pt
```

方式 B：什么都不做，直接启动程序——首次修复或点击「预加载模型」时，
程序检测到权重缺失会**自动下载**（支持断点续传）到 `models/`。

校验信息（SHA-256）：`7ba7aa7ac37a4d41fdbbeba3a2af7ead18058552997e3a3cd1a3b2210c9e6b4c`

模型来源与许可：

- LaMa 论文 *Resolution-robust Large Mask Inpainting with Fourier Convolutions*（WACV 2022），
  官方实现 <https://github.com/advimman/lama>；
  本项目使用的 TorchScript 权重来自 `simple-lama-inpainting` 的官方 release。
- YuNet 来自 OpenCV Zoo（Apache-2.0），仅用于**保护原始人脸**，不参与图像生成。

> 本项目**不包含**通用 Logo 深度学习检测模型。界面里的「Logo 候选」是基于颜色 / 形状的
> **启发式**候选提取，需要人工确认；该类已独立封装，便于日后替换为真实模型。

## 14. 已知限制

- **B 模式**以“OCR 可识别的文字水印”为主要目标。纯图形 Logo、极低对比度、严重模糊、
  特殊字体、与背景严重融合的水印，OCR 读不出来就无法检测；此时程序会**明确提示并跳过**，
  不会假装处理成功。这类场景请改用 C 手动涂抹。
- B 模式按“优先不漏”设计，因此图片里**正常的大段文字（海报标题、字幕）也会被视为要去除的文字**，
  请在候选表格中取消不需要的行。
- **A 模式**是启发式评分，没有标注数据集，因此**不提供准确率 / 召回率**。
- 重复 / 平铺水印在背景极其复杂时可能只找到一部分，可配合 A 模式或手动补齐。
- **自动检测比修复本身更耗时**（实测 1.8 ~ 10.8 s/张，OCR 与旋转扫描占大头），
  批量处理前可先用「只扫描检测」评估。
- 极大图片（> 60 M 像素）会被拒绝，建议先缩小。
- CPU 模式下处理高分辨率图片较慢，建议把处理分辨率上限设为 1280 ~ 1920。
- 去水印属于**图像修复**而非信息恢复：被不透明内容完全遮挡的像素无法还原，
  结果只能是“视觉上合理的推测式重建”。
