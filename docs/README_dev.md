# AI 图片智能修复

一个在你电脑本地运行的图片修复工具：**上传图片 → 在要去掉的水印/文字上涂一下 → 点「AI 去除」 → 下载结果**。

不需要懂任何技术名词，也不需要联网（模型已经放在本地）。

> ⚠️ 请只处理你本人拍摄、创作，或已获得权利人授权编辑的图片。
>
> ⚠️ 马赛克等已经彻底破坏像素的区域，AI 只能根据周围画面「推测式重建」，
> **无法还原真实原始内容**，本工具不做任何“100% 恢复”的承诺。

# 一、普通用户使用说明

## 1. 启动

**方式一（推荐）**：双击桌面上的快捷方式 **「AI 图片智能修复」**。

**方式二**：打开 `D:\AI_Image_Restoration`，双击里面的 **`start.bat`**。

* 会弹出一个黑色窗口，看到 `Starting the web UI ...` 后，浏览器会自动打开
  <http://127.0.0.1:7860>；
* 如果 7860 端口被占用，程序会**自动改用 7861、7862…** 并打开正确地址；
* 第一次启动会加载 AI 模型（几秒钟）；使用过程中**不要关闭这个黑窗口**，关闭它就等于关闭程序。

> 📁 项目安装位置：`D:\AI_Image_Restoration`（桌面快捷方式指向这里的 `start.bat`）。

## 2. 使用（先选模式，再 4 步）

### 2.1 三种模式，按需要选一个（页面顶部一键切换）

| 模式 | 适合什么情况 | 怎么工作 |
| --- | --- | --- |
| **A 智能自动识别** | 不确定水印在哪、想让程序先找一遍 | OCR + 重复性 + 位置 + 半透明特征综合打分，给出**高/中/低置信度**候选，默认勾选高置信度（积极模式含中等） |
| **B 文字全部去除** | 批量处理带文字水印的照片（**推荐**） | 把图片里**所有 OCR 能识别的文字**默认全部划入待去除区域，不做过多的水印打分过滤 |
| **C 手动选择** | 要求最高、位置很明确的水印 | 只用你亲手涂抹的区域，**不做任何自动检测**（第五轮验证过的流程，未改动） |

### 2.2 单张图片：4 步（屏幕上只有这些）

| 步骤 | 操作 |
| --- | --- |
| ① 选模式 | 顶部三个按钮：**智能识别 / 文字全部去除 / 手动选择**。选完后页面只显示这个模式需要的东西。 |
| ② 上传图片 | 左边的「上传图片」点击上传，或拖入、Ctrl+V 粘贴；图片会**立刻完整显示**在下方编辑区。 |
| ③ 选区域 | **手动选择**：直接用画笔涂抹（红色就是要去掉的；橡皮擦可改）。<br>**智能识别 / 文字全部去除**：点一次「自动检测水印 / 自动检测文字」→ 下面出现 **Mask 预览**和一句结论（"发现 N 个候选 / 检测到 N 个文字区域，Mask 覆盖 X%"）→ 满意就点「确认修复」；想改就点「编辑 Mask」后用画笔调整，或展开「检测详情」改表格。 |
| ④ 修复 + 保存 | 点唯一的紫色主按钮 **「开始修复 / 确认修复」**，等几秒；右边卡片显示修复结果，点「保存图片（PNG）」即可下载，「查看对比」可看左右对比图。 |

普通使用**不需要改任何参数**：参数、检测明细、日志、质量报告分别收在
「高级设置 / 检测详情 / 处理日志与批量结果 / 质量报告」四个折叠区里，默认全部关闭。

### 2.3 批量处理（几十张照片一次搞定）

切到模式 **文字全部去除**，页面就是三步：

1. **步骤 1**：点「选择图片」（可多选）或「选择输入文件夹」→ 弹出 Windows 文件夹选择窗口；
2. **步骤 2**：点「选择输出文件夹」→ 同样用系统窗口选保存位置（**不需要手输路径**）；
3. **步骤 3**：点 **「开始批量处理」**（想先看效果可以点「只扫描检测（不修复）」）。

处理时页面只显示一条简单进度（"正在处理 23 / 100：photo023.jpg"）；完成后给出
「成功 / 跳过 / 失败」数量、平均耗时与输出文件夹。**每张图的详细数据都在
「处理日志与批量结果」折叠区里**，不占主界面。

批量处理的几条硬规则：

* **每张图片单独 OCR、单独生成 Mask**（不会把第一张的 Mask 复制给其它图片）；
* **OCR 没检测到文字就明确写"跳过"**，不会假装处理过；
* 单张失败（例如文件损坏）**不会中断整批**，最后会给出"总数 / 成功 / 跳过 / 失败 + 失败原因"；
* 输出文件名是 `原名_restored.png`，**绝不覆盖原图**；同名自动变成 `原名_restored_1.png`、`_2`…；
* 输出目录里自动分好 `restored/`（修复图）、`masks/`（掩膜）、`reports/`（每张 + 批次 JSON 报告）。

> 🖼️ **大图也能看全**：图片尺寸很大或很长时，编辑区会**等比自动缩略**，保证整张图片完整可见
> （不再出现"只能看到上半张"的情况）。缩略只影响显示——原图像素不丢，修复结果仍按
> **原始分辨率**输出，涂抹位置会按比例精确映射回原图（实测偏差 ≤ 1 像素）。

> 🎯 **涂抹不用很精确**：你画的范围只是"告诉程序水印在哪"，程序会自动**收紧**到真正的水印像素，
> 不会把整块背景交给 AI 重画（所以不会留下明显的笔刷形状）。
>
> 🙂 **涂到人脸也没关系**：程序会检测人脸与五官（眼睛/眉毛/鼻子/嘴巴），
> 自动**保护面部结构**、只修水印覆盖的像素；如果水印在脸上过于密集，
> 程序会**主动跳过会破坏五官的部分**并在状态栏说明，而不是把脸重画一遍。

## 3. 效果不理想怎么办

| 现象 | 处理办法 |
| --- | --- |
| 水印边缘有淡淡残留 | 展开「⚙️ 高级设置 → 参数微调」，把 **Mask 扩张** 从 8 调到 12~20，再点一次「AI 去除」。 |
| 修完有接缝感 | 在「参数微调」里勾选 **开启无缝融合**；或把「羽化宽度」调到 10 左右。 |
| 修复区出现偏亮/偏暗的“补丁、阴影、色块” | 先把画笔调细、**Mask 只涂水印本身**（Mask 越小，LaMa 需要"凭空生成"的区域越小）；再把「接缝光照校正强度」调到 0.4~0.6；不要过度扩张 Mask。 |
| 修复区看起来比周围更“糊” | 程序已默认做“颗粒匹配”。若仍偏糊，把「修复区锐化」调到 0.3~0.5，并把「羽化宽度」减小到 3~4。 |
| 图片很大、处理很慢 | 在「参数微调」把 **处理分辨率上限** 调到 1280 或 1920（会自动缩放处理再还原尺寸，保持比例）。 |
| 不想自己涂 | 切到 **A 智能自动识别** 或 **B 文字全部去除**，点「🤖 自动检测并预览 Mask」，确认后再点「✨ AI 去除」。 |
| 自动检测没找到水印 | ① 确认模式：文字水印用 **B 文字全部去除**；② 把「自动检测敏感度」设为 **积极**；③ 极低对比度/严重模糊/纯图形 Logo 用 **C 手动选择**。 |
| 想把检测到的某个区域去掉不修 | 在候选表格里把那一行的「选中」列清空，点「应用表格修改」，再修复。 |

## 4. 常见问题

**Q：黑窗口里出现英文报错？** 页面里的错误提示都是中文；详细技术日志在 `logs/app.log`，把它发给开发者即可。

**Q：网页显示“图片读取失败”？** 请重新上传 JPG / PNG / WEBP 图片；损坏的文件、0 字节文件、文本文件都会被安全拦截并提示，不会让程序崩溃。

**Q：能还原马赛克吗？** 不能。被马赛克覆盖的像素信息已经丢失，AI 只能推测式重建。

**Q：支持中文路径吗？** 支持。项目现在安装在 `D:\AI_Image_Restoration`（桌面已创建「AI 图片智能修复」快捷方式），模型加载、临时文件、输出文件都做了中文/非 ASCII 路径兼容。

**Q：会自动联网吗？** 不会。除首次安装依赖外，运行时完全本地；仅在 `models/big-lama.pt` 缺失时才会尝试下载模型。

# 二、技术说明（开发者 / 进阶用户）

## 1. 处理流程

### 1.1 三种模式是**相互隔离**的模块（重点）

```
              ┌──────────── A 智能识别 ────────────┐
              │                                    │
   模式层     ├──────────── C 手动选择 ────────────┤→ Mask
              │                                    │
              └──────── B 文字全部去除 ────────────┘
                                ↓
                  第五轮修复引擎（唯一入口，保持冻结）
              LaMa + 人脸保护 + 色调匹配 + 纹理恢复 + 融合
                                ↓
                              结果
```

| 模式 | 模块 | 负责 | 允许依赖 |
| --- | --- | --- | --- |
| A 智能识别 | `core/modes/mode_a.py` | 自动水印候选 → Mask | `core/auto_detect.py` |
| B 文字全部去除 | `core/modes/mode_b.py` | OCR 全文字 → Mask（含批量） | `core/auto_detect.py` |
| C 手动选择 | `core/modes/mode_c.py` | 只用用户涂抹 → Mask | 只依赖 `core/mask_processor.py` |
| 修复引擎 | `core/pipeline.py` | 三个模式共用，**不因 A/B 调整而改动** | — |

为了让"隔离"变成可验证的事实，做了两件事：

1. `core/modes/__init__.py` **懒加载**：只有真正调用某个模式时才 import 它的实现；
2. `core/__init__.py` 取消"一次性 import 全部子模块"，改为按需加载
   —— 手动模式下 OCR / 自动检测 / LaMa 都不会被加载（启动也更快）。

`tests/test_mode_isolation.py` 用子进程实测 `sys.modules` 证明：
跑 C 模式时 `auto_detect` / `ocr_detector` / `watermark_detector` **一个都没被 import**；
改 A/B 的敏感度等参数后，C 的 Mask 与修复结果**逐像素不变**。
以后优化 A 只动 `mode_a.py`，优化 B 只动 `mode_b.py`，**都不需要碰 C**。

```
上传 → normalize_image()（统一为 RGB）→ 画笔/自动检测生成 Mask
     → Mask 扩张 → LaMa 深度学习 Inpainting → 色彩匹配 + 羽化融合 + 锐化/降噪
     → 结果图 / 对比图 / 下载文件
```

## 3. 使用的模型与技术

| 环节 | 方案 | 说明 |
| --- | --- | --- |
| AI 修复 | **LaMa big-lama**（TorchScript） | 论文 *Resolution-robust Large Mask Inpainting with Fourier Convolutions*（WACV 2022）；权重来自 `simple-lama-inpainting` v0.1.0 官方 release，196.3MB，已放在 `models/`，CPU/GPU 均可运行 |
| 备用修复 | OpenCV Telea | 传统扩散式修复，仅在 LaMa 不可用时启用，界面会明确标注 |
| 文字识别 | **PP-OCRv4**（RapidOCR + ONNXRuntime） | 模型随依赖包分发，中文 + 英文 + 数字，无需额外下载 |
| 半透明水印 | 中值背景估计 + MAD 鲁棒阈值 + HSV 饱和度分析 | 自研，见 `core/watermark_detector.py` |
| 重复水印 | 行/列投影自相关估计周期 + 平移一致性校验 | 自研，置信度低时会提示改用手动涂抹 |
| 马赛克检测 | 梯度网格周期响应 + 块内平坦度 | 自研启发式，仅给出候选 |
| 后处理 | 局部色彩匹配 → 羽化融合（可选 SeamlessClone）→ 锐化/降噪 | `core/image_processor.py` |

> 本项目**不包含**通用 Logo 深度学习检测模型：界面里的「Logo 候选」是基于颜色/形状的启发式候选，
> 需要人工确认；该类已独立封装，便于以后替换成真实模型。

## 7. 修改记录（本次修复）

网页上出现的 **`Error / tuple index out of range`**，根因是：

> 旧版界面回调返回的 `gr.ImageEditor` 值只有 `background` 和 `layers`，
> 而 Gradio 4.44.1 的 `ImageEditor.postprocess()` 会无条件读取
> `value["composite"]`（`gradio/components/image_editor.py:421`），因此抛出
> `KeyError: 'composite'`，事件失败后编辑器 / Mask 预览 / 局部放大三个区域全部显示“错误”。

修复方式：

1. 新增 `core/error_handler.py`：所有回调统一保护，异常写 `logs/app.log`，页面只显示中文提示；
2. 新增 `normalize_image()`：所有图片入口统一为 RGB，兼容 numpy / PIL / 路径 / bytes / FileData / list / None，
   正确处理 EXIF、透明 PNG、灰度、CMYK，并校验空文件、损坏文件、过小/过大图片；
3. 新增 `mask_processor.make_editor_value()`：**一律**返回 `background + layers + composite` 三个键；
4. 界面按产品化重做：主界面只留 4 步，技术参数全部收进「⚙️ 高级设置」；
5. 新增回归测试（`tests/test_all.py` 测试 12）：逐个回调检查返回值个数与类型，
   并把每个输出真实送进对应 Gradio 组件的 `postprocess`，防止同类问题再次出现。

**第二轮修复（大图 / 竖图在编辑区只能看到一部分）**

根因（真实浏览器 DOM 实测）：

> Gradio 的 `ImageEditor` 把画布按容器**宽度**等比缩放，但外层 `.block` 是
> `height:520px; overflow:hidden` 的固定高度容器。当图片显示后的**高度**超过 520px
> （竖图 1280×1632 会显示成 726×925、细长图 1200×3200 显示成 640×1707）时，
> 下半部分被直接裁掉。横图恰好不超高，所以之前只有竖图 / 大图明显出问题。

修复方式（只改前端显示与坐标映射，未改 LaMa / CUDA / OCR / 修复逻辑）：

1. 编辑器画布改为**等比自适应容器**（CSS：`height:auto; max-height:62vh; width:auto; max-width:100%`），
   外层容器不再固定高度裁切——整张图始终完整可见；
2. 送入编辑器的图片先缩到长边 1800px 的**显示预览**，后端始终保留完整分辨率的原图；
3. 涂抹后，Mask 在服务端按比例缩放回原始分辨率再交给 LaMa，
   **修复结果按原分辨率输出**（3840×2160 的图，输出仍是 3840×2160）；
4. 新增 `tests/test_all.py` 测试 13：对 900×640 / 1920×1080 / 2560×1440 / 3840×2160 / 竖图
   逐一校验"原图分辨率不变 + 预览已缩略 + 掩膜位置正确"，实测偏差 ≤ 1 像素；
5. 真实浏览器复测：六种尺寸全部完整显示；在 3840×2160 图上按已知位置涂抹，
  掩膜中心与期望位置偏差 **1 像素（0.03%）**。

**第三轮修复（修复区出现阴影 / 色块 / 补丁感）**

量化诊断（用真实照片 + 6 个可控场景，脚本：`tests/quality_report.py`）后确认三个原因：

> 1. **Mask 过大**：默认画笔 26px + 扩张 8px，一次涂抹就把水印周围大量正常背景圈进去，
>    LaMa 需要"凭空生成"的面积变大，色差与纹理差随之放大；
> 2. **旧的色彩匹配方式有害**：它按全局均值/方差改写整个修复区，实测让修复区比周围
>    偏暗 **-21（LAB）**，正是你看到的那块"暗紫色补丁"；
> 3. **旧羽化把接缝做成了硬边**：接缝梯度达到原图的 **1.74 倍**（1.0 为自然），肉眼就是轮廓/光晕。

新的融合策略（`core/image_processor.py`，LaMa / CUDA / OCR 逻辑均未改动）：

1. **Mask 收紧**：默认画笔 26→18px、Mask 扩张 8→4px（越小越不容易出现补丁）；
2. **平滑羽化融合（soft_blend）**：用距离变换生成 smoothstep 过渡，
   边界处交给原图、中心 100% 用模型输出；过渡宽度按 Mask 厚度自动收缩，
   且**只作用于 Mask 内部**（Mask 外像素保持原样）；
3. **接缝光照校正（match_local_tone）**：把 Mask **外围**的真实光照低频场用归一化卷积
   插值进 Mask 内部，只在接缝附近施加（向内衰减到 0），既修正明暗不一致，
   又不会把水印本身的亮度带回来、也不会整块改色；
4. **颗粒匹配（match_local_grain）**：测量周围的高频（布料/传感器）能量，
   在修复区补上同强度颗粒，消除"过于干净/发糊"的补丁感；
5. 锐化改为在**收缩后的 Mask** 内进行，避免在接缝上制造光晕。

实测（旧融合 → 新融合，`tests/quality_report.py`）：

| 场景 | 接缝倍数 | 与真值 MAE | 说明 |
| --- | --- | --- | --- |
| 你的真实照片 | 1.35×/1.74× → **0.94×** | — | 修复区与周围亮度差从 -21.0 → -8.1（LaMa 原始输出为 -7.7） |
| 渐变背景+文字水印 | 1.18× → **0.97×** | 3.57 → **3.37** | 颗粒匹配 1.18 → 1.07（1.0 为一致） |

**第四轮修复（笔刷印记 + 人脸被 AI 改写）**

真实使用中发现的第二个严重问题：**用水印覆盖整张脸时，LaMa 会把整张脸"重画"**（五官变形）。
排查后确认根因有两层：

> 1. **用户涂抹范围被原样当成"要重建的区域"**：15 道粗笔触互相重叠 → 一张覆盖 55% 画面的巨大 Mask，
>    LaMa 只能大面积"重画"，头发、布料纹理与五官都会被改写；
> 2. **旧流程没有区分"涂抹范围 / 水印核心 / 必要扩张"**，也没有人脸结构保护。

本轮实现（`core/mask_refiner.py` + `core/face_protector.py`，LaMa / CUDA / OCR 全部沿用）：

1. **Mask 自动收紧（Brush → Watermark Core）**：在"用户涂抹范围"内，用
   **OCR 文字框 + 半透明水印检测 + 局部对比度残差**估计真正的水印像素；
   证据不足时只做**温和内缩**（不做激进收缩，避免水印残留）；
   最终 Mask 永远不超过"用户涂抹范围 + 2px"，**绝不外扩**；
2. **严格模式**：当用户把整张图都涂上（>30% 画面）时，自动忽略容易误判的对比度残差、
   不做形态学粘连，把水印碎片保持为**彼此分离的小块**；
3. **人脸检测与三档策略**：YuNet（含 5 点关键点，位于 `models/face_detection_yunet_2023mar.onnx`，
   227KB）→ 判定 `normal / face_edge / face_protect`；面部范围内扩张收紧到 1~2px、
   羽化 3~4px、**禁用颗粒匹配**（皮肤不加噪声）、锐化上限 0.15；
4. **五官硬保护**：某个五官（眼/鼻/嘴）被水印覆盖超过 45% 时，
   只允许修复其中的**细小碎片**，**跳过过大的遮挡块**——宁可留下少量水印，也不让 AI 改写五官；
5. **分块局部重建（tile-mode）**：碎片多/面积大时，把 Mask 拆成若干块，
   每块只用**局部 ROI** 让 LaMa 重建（局部上下文 = 皮肤/布料纹理），
   从根本上避免"整块重画"；同时给出"重建面积过大，建议分次修复"的提示；
6. **面积上限**：水印核心若超过画面 25%，自动内缩并明确告知（超出后 LaMa 会重画整幅图）。

**第六轮（模式 A/B/C + 原生文件夹选择 + 自动检测重写 + 性能统计）**

本轮没有改动第五轮的修复算法（LaMa / 双 Mask / 人脸保护 / ROI / 高频纹理匹配 / quality_check 一行未动），
只重做"自动检测"这一层，并把界面按使用模式整理。

1. **新增三种模式**：A 智能自动识别 / B 文字全部去除 / C 手动选择；
   **C 模式走的是完全相同的第五轮路径**（`auto_mask=None`，只用用户涂抹的 Mask），
   回归实测：Mask 外改动 0.000%、笔刷泄漏 0.00%、五官区最大变化 0。
2. **自动检测引擎重写**（`core/auto_detect.py`）：多尺度 OCR + 整图旋转扫描（±25°/±45°）+
   文字笔画聚类后的**逐块去倾斜放大 OCR** + 文字行/文字块合并（昵称 + 账号 + 小图标合成一块）+
   模板聚类 + 模板匹配 + 点阵展开（重复/平铺水印找齐全部实例）；
   置信度分高/中/低三层，**中等候选也会进入 Mask 预览**，而不是被阈值丢掉。
3. **Mask 更贴合文字**：候选 Mask = 旋转矩形内的**实际文字笔画**（局部对比度）× 小范围扩张，
   不再是"一个大矩形"，避免把整张脸/整件衣服交给 LaMa。
4. **输入/输出文件夹都用 Windows 原生选择窗口**（`core/folder_picker.py`，tkinter → PowerShell 两级兜底），
   界面不再要求手输路径；输出目录不存在自动创建、不可写会明确提示。
5. **绝不覆盖**：输出名 `原名_restored.<ext>`，同名自动 `_1`、`_2`…（`unique_output_path`），
   批量实测两次运行后生成 `*_restored_1.png`，原图哈希不变。
6. **批量处理**：选择输入文件夹 → 逐张**独立** OCR/Mask → 第五轮修复 → 输出；
   单张失败不中断；跳过/失败原因写入表格与批次 JSON；"仅检测不修复"模式可只出 Mask 与报告。
7. **性能统计**：每张图记录 OCR / Mask 收紧 / Mask 生成 / 人脸 / LaMa / 后处理 / 质检 / 总计；
   批量结束输出总数、成功、跳过、失败、平均每张与阶段平均值（实测：**OCR 是当前主要瓶颈**）。

本轮修掉的两个真实缺陷（都会直接导致"检测不到 / 检测错位"）：

> 1. `_rect_from_points()` 的"长边/角度"判定写反了——水平文字被判成 89°，
>    去倾斜时反而把文字转成竖条，导致局部 OCR 读不出来、Mask 位置错误；
> 2. 旋转扫描 / 局部放大两路 OCR 的坐标没有统一回"检测坐标系"，
>    导致同一处水印出现偏移的重复候选。

**真实浏览器联调后又修掉的三个缺陷**（都是"用起来才会暴露"的问题）：

> 1. `_envelope()` 把 `(x, y, w, h)` 这种**轴对齐框**当成"两个坐标点"来 reshape，
>    于是候选去重时重叠判断全错：A 模式下真正的整块文字水印被一堆小碎框挤掉，
>    结果"只框住两个小点、Mask 只有 0.07%"。现在支持三种输入（旋转矩形 / 轴对齐框 / 角点），
>    并改成"先按面积把被包住的碎块并入大框，再按置信度做 IoU 去重"。
>    实测同一张图上 A 模式与 B 模式现在都给出整块水印（Mask 0.951%）。
> 2. 某些前端布局下 `ImageEditor` 回传的 `composite` 与 `background` 不可比，
>    差异推断会得出"整张图都被涂过"。现在两条路径都加了安全阀（覆盖率 > 90%/95% 直接忽略），
>    保证"用户没涂到的地方绝对不修改"这条底线在真实浏览器里也成立。
> 3. `make_temp_path()` 用了 `time.strftime("%f")`（`%f` 只有 `datetime.strftime` 支持），
>    导致"下载副本"生成失败（日志里是 `Invalid format string`），已修正。

**第八轮（B 模式稳定性：去得更完整，而不是把 Mask 扩大）**

用真实失败案例（草地重复红字、茶壶/月饼平铺字、女孩平铺字、猫、海豚）逐实例诊断后，
确认 B 有两个"看起来很玄"的问题其实都有明确机制：

1. **LaMa 会把文字"抄"回来**：B 的掩膜是紧贴文字的笔画掩膜，而
   `clip_to_user(..., allow_px=0)` 会把计划里的扩张整段裁掉，于是**送进模型的孔洞是"零余量"的**；
   LaMa 在零余量孔洞里会顺着两侧像素复现原文字（实测残留 21.4%，红字变成金黄色块）。
   → 新增 `RepairOptions.hole_grow`：**只把模型孔洞扩开 6px，写回范围一点不变**
   （残留 21.4% → 0.2%，Mask 面积 4.76% → 4.76%）。
2. **重复水印的部分实例被收紧阶段删掉**：模板匹配 / 点阵展开补出来的实例没有 OCR 框，
   `mask_refiner` 把它们当噪声内缩甚至整块删除（实测掩膜覆盖率 100% → 0%，
   于是那一处水印完全没被修 —— 这就是"有些实例成功、有些失败"的原因）。
   → 新增 `RepairOptions.keep_user_instances`：被收紧掉超过 25% 的实例按检测到的形状整块保留。

两个开关都通过 `core/modes/mode_b.py` 的 `repair_hints` 下发，**只对 B 生效**；
A/C 默认为 0/False，行为与之前逐像素一致（C 回归：Mask 外改动 0.000%、笔刷泄漏 0.00%、
五官区最大变化 0.0）。

真实案例实测（6 张图 / 54 个实例）：实例成功 **26 → 47**，掩膜对文字像素覆盖率
**79% → 94%**，结构相关度 **0.31 → 0.19**（0 = 水印已消失）。

**第七轮（UI 简化 + A/B/C 模块隔离）**

1. **模式层落地**：新增 `core/modes/`（`base.py` / `mode_a.py` / `mode_b.py` / `mode_c.py`）。
   界面和批处理只调用模式对象产出 Mask，修复统一交给
   `core/pipeline.run_repair()`——A/B 以后单独改，C 的手动流程不受影响。
2. **懒加载**：`core/modes/__init__.py` 与 `core/__init__.py` 改成按需 import，
   手动模式的运行路径里不会出现 OCR / 自动检测（`tests/test_mode_isolation.py` 实测）。
3. **界面重做**：标题 + 副标题 + 三个模式按钮；① 上传并涂抹、② 修复结果左右并排；
   每个模式只有一个主按钮；参数 / 检测明细 / 日志 / 质量报告各归入折叠区，默认关闭。
4. **状态口语化**：主界面只显示「✓ 图片已加载」「✓ 检测到 N 个文字区域」
   「✓ 修复完成（4.1 秒）」这类短句，技术细节进「处理日志」。
5. **修复流程零改动**：LaMa / 双 Mask / 人脸保护 / ROI / 色调匹配 / 纹理恢复/
   `quality_check` 全部原样保留；C 模式回归实测 Mask 外改动 0.000%。

## 8. 已知限制

* **B 模式（文字全部去除）以"OCR 可识别的文字水印"为主要目标**：纯图形 Logo、
  极低对比度、严重模糊、特殊字体、文字与背景严重融合的水印，OCR 读不出来就检测不到，
  这类请用 A 模式或 C 手动涂抹；程序会在"未检测到文字"时**明确提示并跳过**，不会假装成功；
* B 模式按需求"优先不漏"，因此图片里**正常的大段文字（海报标题、字幕）也会被当作要去除的文字**，
  请在 Mask 预览/候选表格里取消不需要的行；
* A 模式的 Watermark Score 是启发式评分（类型 + 位置 + 重复性 + 透明度 + 人脸冲突），
  没有标注数据集，因此**不提供"准确率/召回率"这类数字**，只报告真实测试的检测数量；
* Logo 检测仍是启发式候选，不是深度学习模型，复杂 Logo 需要手动涂抹；
* 重复/平铺水印在背景极其复杂时可能只找到一部分，可配合 A 模式或手动补齐；
* 自动检测比修复本身更耗时（实测 1.8~10.8s/张，其中 OCR + 旋转扫描占大头），
  批量处理前可先「只扫描检测」评估；追求速度可在「高级设置」把敏感度改为 **平衡**；
* 极大图片（>60M 像素）会被拒绝，建议先缩小；
* CPU 模式下处理高分辨率图片较慢，建议把处理分辨率上限设为 1280~1920。
